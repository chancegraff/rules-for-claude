# Plan Convergence Runbook

Operator mechanics for running `plan-convergence-run-v2` on any plan. The methodology lives in `SKILL.md` beside this runbook.

Terms. The state directory is `~/.claude/plans/<project>/<plan-name>/`, where `<project>` names the project and `<plan-name>` is the plan's filename with `.md` removed. The round records are the files under its `records/` directory: `round-<n>.json`, the record builder's; `round-<n>-verdict.json`, the verdict engine's; `round-<n>-entries.json`, the entries file the synthesizer, the adjudicator and the replacement reviewer write; `round-<n>-recorded.json`, the recorded-edits file the lead writes; and, under `records/checks/`, the check files `round-<n>-facts.json`, `round-<n>-pointers.json`, `round-<n>-candidates.json`, `round-<n>-baseline.json` and `round-<n>-anchors.json`. The synthesis is `round-<n>-synthesis.md` and the builder's derivation `builder-derivation-round-<n>.md`, both in the state directory. The status page is its `STATUS.md`. The hook logs are `~/.claude/hooks/logs/edit-provenance.jsonl`, `read-provenance.jsonl` and `agent-usage.jsonl`, and the meter log is `~/.claude/usage-meter-log.jsonl`. The modules a runner invokes by path live under `~/.claude/lib/plan-methodology/`. A launch supplies the run's `args`: `planPath`, `startRound`, `stateDir`, `repoRoot`, `boardPath`, `leadSessionId`, the optional `endRound`, the round after which a `round continues` or plateau verdict ends the run instead of opening the next round, absent by default, and the optional `convergenceSkillPath`, the skill file the freshness pass, the verify-new seat, the builder seat and the class-audit seats read, defaulting to `~/.claude/skills/plan-convergence/SKILL.md`. A by-name launch supplies `args` only through the harness's parse of the invocation, never as exact literals. A launch that must carry exact paths and a session id therefore goes through the Workflow tool, with the script body supplied directly.

## 1. Launch checks

Run every check at every launch.

1. **The subagent-model override.** Read the `env` block of `~/.claude/settings.json`. Confirm that it carries no `CLAUDE_CODE_SUBAGENT_MODEL`, unless the run deliberately pins one model. The variable overrides both session inheritance and every model the script requests per stage.
2. **The arguments.** Supply `planPath`, `startRound`, `stateDir`, `repoRoot`, `boardPath` and `leadSessionId` on every launch. Supply `endRound` where the run must stop after a given round on a `round continues` or plateau verdict, as a calibration or a dry run does; leave it absent to let the run continue until it converges or halts. Supply `convergenceSkillPath` only where a copy of the skill is under test; every other launch takes the default.
3. **The hooks.** Confirm that `~/.claude/settings.json` registers `edit-provenance.js` under `PostToolUse` and `PostToolUseFailure` on `Edit`, `read-provenance.js` under `PostToolUse` on `Read`, and `agent-usage.js` under `SubagentStop`. The record builder joins their logs to the run's journal; without them a record carries no entry outcome, no usage and no read lines, and every entry reads as unattempted.
4. **`leadSessionId` and the adjudicator seat.** Set `leadSessionId` to the launching session's id; the run resolves the workflow transcript root through it, and the record builder reads the run's `journal.jsonl` there. Design calls go to the in-workflow adjudicator seat, which rules from the durable record: the plan, every round record in `records/`, the standing board backup, the repo CLAUDE.md, the round's synthesis, the round's entries file and the recorded-edits file, for the lead's rulings. A call the record cannot settle returns `unadjudicated`, and a call in the human's reserved set returns `reserved`. Either one skips the replacement review, the anchor check and the application; the record builder, the verdict engine and the narrator still run, and the run ends on the verdict `design call` or `reserved decision`.
5. **The launch marks.** The freshness pass excludes the plan's State-section facts that only the launching session can open; no subagent can open them on any agent type. Re-read each of them at launch and record a launch mark per fact, naming the fact, its site and the value read. Before a plan's first launch the marks go in the round-0 seed's `launchMarks`. At every later launch, a relaunch after a halt, a relaunch at the round after `endRound`, or a first v2 launch on a converted record, re-read the facts again and record the marks in the launch round's recorded-edits file, `records/round-<n>-recorded.json`, whose `launchMarks` stand in place of the previous record's; the freshness pass and the record builder read them there, and the record carries them forward. The freshness pass verifies a session-scoped row against the recorded value, never against the world. Without the marks, no actor ever verifies a session-scoped row, and the converged exit is unreachable. When a re-read falsifies one of those facts, record the falsification as a correction in that same recorded-edits file's entries (`SKILL.md`, Round records); the round's synthesizer carries it into the entries file, the anchor check tests it, the applier applies it, and the record puts its site in the next round's target set.
6. **The ways a run stops mid-flight.** A run can stop mid-flight and return nothing in these ways: a pause on an agent permission prompt; a session limit reached mid-run; the run reaching the per-run agent budget; a throw from the script body itself, the throwing globals (`Date.now()`, `Math.random()`, argless `new Date()`) among its causes; and the lead's own stop on a mid-round correction. Record every such stop on the board as a runtime failure. Then recover it per part 2.
7. **The round-zero write.** Before a plan's first launch, write `records/round-0.json`, creating `records/`: a JSON object carrying `round` 0, `nextInventory` (the round-1 claim inventory, one row per checkable claim with its `number`, `class`, `claim` and `site`), an empty `nextTargetSet`, and `launchMarks`; leave every other field absent. Write it indented, one field per line. A run that starts with no inventory rows would meet the every-row-verified condition vacuously, so this write always precedes the first launch. Round 1's verify-new seat reads no site and returns an empty verdict list.
8. **Corrections.** Between runs, a correction, a purely additive edit, a ruling, or the stall sweep's blocks go into the launch round's recorded-edits file, on the parts and occasions `SKILL.md`'s Round records section states: entries in the entries file's shape, each id carrying the lead's prefix (the literal `schema-entries-file.ts` under `~/.claude/src/plan-methodology/plan-convergence-run-v2/` fixes) and the recorded-text mark set; rulings by site; launch marks. Never edit the plan by hand between runs, and never edit a round record.

## 2. Crash recovery

Recovery reads the record. On every round, halted or not, the record builder writes `records/round-<n>.json`, the verdict engine `records/round-<n>-verdict.json` and the status narrator a section of `STATUS.md`, unless one of those three stages failed, in which case the run's return names it as the failing stage.

What the lead reads from the record: `lastStageReached`; `failedSeats`, `failedModules` and `unattributedFailedKeys`; each seat's outcome, usage, span, read lines and meter readings; `markedEntries`, each with its `outcome`, applied, failed or unattempted; `designCalls` with their rulings; `nextTargetSet`; `nextInventory`; `verifiedRowCount` over `rowCount`; and `closingMeterReading`, for the round's cost and quota. A halted round's record carries no field of a stage the round never reached.

### Exit kinds and the run's return

Every run ends by returning `endKind`, `round`, `stateDir`, `synthesisPath` where that round's synthesizer returned, and `failedStage` on a runtime failure. The kinds, highest first: runtime failure, reserved decision, design call, plateau, converged, round continues. The verdict engine computes the highest kind whose test holds from the round record and the previous three records, and writes every other kind the record also satisfies as `otherKinds`. A `round continues` or plateau verdict opens the next round, or ends the run after the narrator when the round is `endRound`; every other kind ends the run after the narrator. A mid-flight stop returns nothing; the lead reads the last record and verdict file the run left.

### Acting on a kind

| State | Event | What the run leaves | Round the lead launches |
| - | - | - | - |
| any stage before the record builder | a seat, a runner among them, returns null | the round's stage sequence stops; the record builder, the verdict engine and the narrator run; the record names the seat in `failedSeats`; the verdict is `runtime failure`; the return names the stage | the next round when the record shows an edit landed (a marked entry with outcome applied), else the same round |
| any runner before the record builder | its module fails | as above, the record naming the module in `failedModules` | the same round |
| the record builder | its module fails or its runner returns null | no record; the return names the record builder | the same round |
| the verdict engine or the status narrator | its module fails, its runner returns null, or the seat returns null | the record, and the verdict file where written; the return names the stage | the next round when the record shows an edit landed, else the same round |
| the adjudicator | a call comes back `unadjudicated`, or is `reserved` | the replacement review, the anchor check and the application are skipped; the record carries the call with its ruling; the verdict is `design call` or `reserved decision` | the same round, after the lead records the ruling, the human's decision for a reserved call, in that round's recorded-edits file |
| the verdict engine | `converged` | the record, the verdict file, the status entry | none; the end gate follows (`SKILL.md`, Approval bar) |
| the verdict engine | `plateau` | the record; the verdict file naming the three rounds compared; the status entry; the run opens the next round, or ends at `endRound` | at `endRound`, the round after; between runs the lead may launch `plan-stall-sweep-run-v2` on the rounds the verdict file names (`SKILL.md`, The plateau response) and record the blocks its return carries in the relaunch round's recorded-edits file |
| the verdict engine | `round continues` | the record, the verdict file, the status entry; the run opens the next round, or ends at `endRound` | at `endRound`, the round after |

A relaunch at the same round writes every round-keyed file in place: the check files, the entries file, the synthesis, the derivation, the record and the verdict file. `STATUS.md` alone keeps the earlier attempt's section, the later attempt's section added above it.

### A mid-flight stop

A mid-flight stop leaves no record for the round it stopped in. That round is the run's `startRound` when the run wrote no record, and otherwise the round after the last record the run wrote. Relaunch at that round, with the launch marks re-read into its recorded-edits file (launch check 5). Where the stop was the lead's own on a correction, record the correction in that same file first.

A dead run's journal is `journal.jsonl` under the launching session's directory in `~/.claude/projects/`: `<project-slug>/<session-id>/subagents/workflows/<run-id>/journal.jsonl`. The record builder reads it; the lead reads it only for a stop no record covers. Each `result` event carries `seat` and `round`, so the halted round's events are the ones after the last result carrying the previous round number. Where the journal shows the applier's `started` event for the halted round, the plan may carry that round's edits with no record of them; the lead may then run the record builder and the verdict engine by hand on that round, each module invoked by its path with no interpreter, `~/.claude/lib/plan-methodology/round-record.js <planPath> <stateDir> <round> <transcriptRoot>` and then `~/.claude/lib/plan-methodology/verdict.js <planPath> <stateDir> <round>`, the transcript root being `~/.claude/projects/<project-slug>/<session-id>/subagents/workflows`, so the round gets its record and its verdict file, and relaunch at the round after.

## 3. The seeded-defect calibration

The calibration measures the opening-barrier seats' per-shape catch rate against a known answer key, and tunes the defect-shape checklist their briefs carry. v2 is gated on it: the first v2 calibration must match or beat the recorded baseline before any plan converges on v2.

1. Copy the plan under a `-calibration` filename, `<plan-name>-calibration.md`, into that filename's own state directory, `~/.claude/plans/<project>/<plan-name>-calibration/`. That directory never collides with the plan's own.
2. Inject into the copy defects of the seat-checklist shapes: the shapes on the defect-shape checklist the seat briefs carry.
3. Record `seeded-defects.md` beside the copy, in that same directory: one row per injected defect, carrying its site, its shape, and the corruption made. This file is the answer key every returned finding resolves against.
4. Write the round-0 seed into that directory (launch check 7), with the launch marks, and launch `plan-convergence-run-v2` with `planPath` the copy, `stateDir` the calibration directory, `startRound` 1, `endRound` 1 or 2, `boardPath` the plan's own board, and `repoRoot` and `leadSessionId` as the session supplies them. Every stage runs on its normal model, effort and reads, the calibration directory as the state directory, and round 1 runs through to `records/round-1.json`.
5. Read the catch rate per shape from round 1's record, each seat's `findings` by site and claim, against the answer key, on the key's own counting rule. Read the record's `markedEntries` for phantom failures: no entry the record marks failed whose site carries its REPLACEMENT text.
6. Record the catch rate on the board.
7. Refresh the seats' defect-shape checklist against it. The checklist lives in the v2 workflow's brief sources, `brief-defect-shape-checklist.md` under `~/.claude/src/plan-methodology/plan-convergence-run-v2/`. Edit it there, then run `pnpm --dir ~/.claude build`, the `build` script of `~/.claude/package.json`, which carries the refresh into `~/.claude/workflows/plan-convergence-run-v2.js`. Never edit the built workflow file by hand.

The calibration writes nothing outside its own directory beyond the board record and the hook logs every session's hooks append to. A calibration launch that stops mid-flight is recovered by a fresh launch of the calibration, not by part 2's table: the copy and its state directory stand as the stopped launch left them, and a relaunch at the same round writes every round-keyed file in place.
