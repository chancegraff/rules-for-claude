# Every Thing Is Finite

No one thing may be boundless; every individual thing must be finite. A hard rule, cross-project, for the lead and every agent, for everything already built or planned and for everything new.

**How to apply:**
- Before writing any loop, list, file, queue, retry, wait, register or archive, name the way it stays finite and where any number comes from. No way named, no thing written.
- The ways: a limit from a measurement or a budget, never a guess (a list's biggest size read from the records; a run's spending limit); a cleaning that keeps it small (closed items removed, old entries folded into one summary line, a rolling window that keeps only what is still read, duplicates merged); an end (a run ends, a plan freezes and retires, a session closes); or a cut into finite pieces, each with its own end (one file per version or per plan). A loop that ends "when it finds nothing new" still carries a hard limit behind that end.
- A thing with none of these ways is a defect, wherever it sits: code, a plan, a skill, a brief, a page, a record, a rule.
- A boundless thing found while reading or building is fixed there and then, never left as "pre-existing". There is no general sweep of old work: a document's accumulated discipline drift gets its own pass instead (`sweep-methodology.md`).
- Every agent brief states this rule in one sentence. The sentence is a reminder, not enforcement.

**Chance's word on a case wins.** When his ruling on a case and this rule differ, his ruling wins and this rule is read as narrowed for that case. One case is ruled already:
- A convergence run carries no round count, no token limit and no refused launch. Its end is its exit table: converged, or no edits across the stall window. This rule's "a run's spending limit" is off for a convergence run.

Earlier rulings this rule narrows and does not break: "no round caps, no numeric limits", "no fixed counts", "no round carries a fixed point cap; the quota rule is the only ceiling", "no cap" on the intake's generation rounds and "never capped" asks, and the knowledge-graph rule "no caps or truncation anywhere". Each of those rejected a number picked by feel, and that form stays rejected. Where one of those things still needs a bound, the bound comes from a measurement or a budget.

The breaks of this rule and what was tried: `~/.claude/incidents/by-rule.md`.
