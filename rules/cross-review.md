# Cross-Review by Implementers

In team workflows (jira-ticket-workflow, team-dev-workflow, and the like), the implementation teammates review each other's work: dev A reviews dev B's files and vice versa. Never spawn dedicated reviewer agents (no `reviewer-for-X`, no standalone QA reviewer agent); implementers already hold the context, and extra agents add cost without insight. Never shut implementers down before cross-review completes. State the review assignments in the plan (each implementer assigned another implementer's files). The lead does the final holistic pass personally. Verification (lint/types/tests) is not a substitute for code review. Cross-review AND the independent lead review both run before committing. See [agent-lifecycle](agent-lifecycle.md) for reuse rules.
