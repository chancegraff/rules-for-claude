# Mirror, Don't Extract

When you are asked to make X "use the patterns" of reference Y, X mirrors Y's structure: consistency comes from parallel structure, not from extracting shared machinery. Never import Y's own components into X; X gets its own. Invent no abstraction Y lacks ("does the reference have that helper?" is the test), and build nothing at a finer granularity than Y uses. X keeps its own design (layout, icons, data ownership); only the structure is mirrored.

A new helper function exists only when the reference already has one, or when a second caller needs it; inside one transform, inline it. [inline-immutable](inline-immutable.md) carries the same sentence.

Read the whole precedent before mirroring it. "Did you look at ALL the code" means the entire pattern family, not the first matching file: when pointed at a precedent area, enumerate and read the WHOLE area (all sibling components, their hooks, stories, tests, the mocks directory, and, when the user has put the stack in scope, every stack branch) before choosing which piece is the pattern. "Match X's pattern" means pattern-match at the FILE level first: list X's directory, map file-for-file, and only then map internals; matching internals while inventing a file layout the precedent doesn't have is the failure mode. Read the whole precedent file, including its bottom exports and default-export wrapper, before mirroring any part; a thin wrapper and export block at the bottom can BE the pattern.
