# Mirror, Don't Extract

When making X "use the patterns" of reference Y, the target MIRRORS the reference's structure; two implementations presenting the same data can differ in design but must be consistent in how functionality is built, and consistency comes from parallel structure, not from extracting shared machinery. Share hooks/utils, but NEVER import the reference's components into the target; the target gets its own components. Invent no abstraction the reference lacks ("does the reference have that helper?" is the test): if the reference formats values with a file-local function, the target does the same inline, no standalone helper. Create no components below the granularity the reference uses (reference at row level means no per-cell components; rows render name+value inline). Keep the target's own design (layout, icons, query ownership); only the architecture/patterns are mirrored.
