# Format-Agnostic Utilities

Shared parse/traversal utilities stay output-agnostic: no baked-in output shape, labels, separators, or return type. The util hands the caller raw structural data and the caller formats. Expose enough raw context that callers lose no information: the full key path, not just the immediate/last key, even if the current caller only renders the last key. A deep parser parses to leaf scalars and passes the COMPLETE key chain (object keys as strings, array indices as numbers) so no ancestry is lost; every label/format/return-type decision lives in the reducer at the call site. The generic accumulator and return type belong to the caller (`parse<T>` returns `T`). An array item's key IS its index; don't pass a separate `index` param alongside an `undefined` key. Never re-stringify a value the parser already parsed (a `JSON.stringify` inside a reducer fed by a deep parser is the anti-pattern).
