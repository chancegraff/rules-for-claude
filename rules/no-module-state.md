# No Module State

No module-level mutable state, no singletons (never export a module-scope instance of a stateful class), no exported reset-for-tests helpers. Hidden module globals leak state across tests and consumers, force test-only reset exports (an API smell), and clash with the pattern where stateful components are classes with private fields; an old module-state precedent in the codebase is not license to repeat it in new code. State between calls lives in a class instance (private fields), constructed at the composition root; tests construct fresh instances instead of resetting globals. When one implementation needs a lifecycle capability, extend the shared interface and registry so it runs for every implementation; never bolt a bespoke method onto one class. The user's shorthand "X already is a class" means "extend the existing abstraction, no one-off shapes", not "give the implementation its own method".
