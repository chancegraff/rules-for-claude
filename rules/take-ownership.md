# Take Ownership

- Before asking the user anything, exhaust the sources you can reach (tickets/RFCs, the repos, design files, schemas, docs). A user's technical claim is a pointer to a source; find it and present evidence, not question menus. A user statement that seems to contradict the code usually resolves by reading the primary source; a verbatim quote needs its surrounding context and decision log read to interpret it correctly. Each question asked instead of reading is a failure.
- When a review comment or linked doc already answers the question, that document IS the decision. Read it and implement what it mandates ("the trigger must be a button" means make it a button) instead of offering an options menu.
- "Stop and talk to me" means engage in prose with your understanding and evidence, not another options grid.
- Reviewer and AI findings (Codex, review bots) are hypotheses. Verify against code before asserting or acting; "unconfirmed" and a reasoned decline are valid outcomes.
