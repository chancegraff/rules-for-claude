# Worktree Setup for Teammates

An agent's shell and git run in the working directory pinned at spawn; `cd` and `git -C` are denied, and absolute-path file tools don't extend to git or yarn. A teammate can therefore only work a worktree its session is pinned to. Assigning a worktree path in a brief and expecting the teammate to reach it on its own produces the "interrupted" idle spiral.

Two provisioning paths, no others:

1. New-branch work: spawn the teammate with `isolation: "worktree"`; the harness creates the worktree and pins the agent inside it. The two paths do not compose: an isolation-spawned agent that later calls EnterWorktree gets a split-brain (the tool reports success and file tools repoint, but Bash and git stay pinned to the spawn worktree and refuse to run in the target). Verified live 2026-07-21.
2. Specific existing branch: `git worktree add <main-checkout>/.claude/worktrees/<name> <branch>` with the ABSOLUTE path under the MAIN checkout (create that directory first if missing; the command works from any worktree of the repo, so a lead pinned in a linked worktree passes the absolute path rather than a relative one). The teammate's first action is `EnterWorktree` with `path` set to that directory. EnterWorktree resolves the repo root through git's common dir to the MAIN checkout, so the only location it accepts is `<main-checkout>/.claude/worktrees/`; a `.claude/worktrees/` nested under a linked worktree is rejected even though git registers it. This rule is the standing instruction that authorizes the EnterWorktree call. Ad-hoc worktree locations (e.g. `~/worktrees/...`) are unreachable for teammates: EnterWorktree rejects them and the shell cannot cd to them. After a further switch, an agent's previously visited worktrees become read-only to it.

Pre-flight before any spawn: each assigned worktree has its dependencies installed and the right branch checked out. Installs are the user's to run; ask for `! yarn --cwd <worktree> install` (or the repo's equivalent) and wait for completion BEFORE dispatching the teammate, since mid-stream provisioning failures surface as opaque teammate interrupts. The spawn brief states the assigned worktree path and the EnterWorktree-first step. One teammate per worktree; the lead neither mutates a teammate's worktree nor pins a teammate into one the lead is mutating ([no-exploration-agents](no-exploration-agents.md)). Blockers that surface anyway escalate per [teammate-blockers](teammate-blockers.md).
