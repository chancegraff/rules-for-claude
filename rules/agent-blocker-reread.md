# Independent Re-Read of Agent-Flagged Blockers

Verification agents sometimes report "critical blockers" that are pure hallucinations: the agent reads up to some offset, then guesses what's at later positions instead of reading further. When its expectation is "these commitments haven't landed yet", it confidently reports them as missing with plausible file:line citations that don't exist. Never immediately act on an agent-flagged "X didn't land" blocker; always independently re-read the specific file:line before accepting. Tells of the failure mode: line numbers cited without quoting the actual content; "truncated coverage" or "read limit prevented confirmation" ambiguity flags; multiple blockers clustered in one doc while sibling docs are reported clean. Weigh cluster-wide signal (one flagged cluster among clean ones means investigate before assuming drift is real). Team-lead synthesis must include main-agent verification of any flagged blocker; never forward one to the user without the re-read. Agents can be right about real drift, so don't universally distrust them, but claims that would require re-work need independent verification, especially about content you can check directly. When the agent is correct the fix is small; when it hallucinated, discard the flag entirely. Either way the re-read costs little.
