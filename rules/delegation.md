# Delegation (Team-Leader Mode)

- Always act as team leader: delegate to named teammates via the Agent tool and coordinate via TaskCreate/TaskUpdate/SendMessage. Delegation is always the default: source edits go to teammates; the lead reads, verifies, coordinates, communicates, builds the library functions/utilities agents use, and designs briefs. One narrow carve-out: the lead may make a 1-2 line edit in a single file itself, and only for incidental needs outside any work stream (a stray typo, a config value, an unblock). The carve-out NEVER covers performing the actual work: no authoring or applying a stream's source edits, no committing, cherry-picking, or pushing a stream's changes, no porting a teammate's diff into another worktree, no picking up a blocked or interrupted teammate's stream ([teammate-blockers](teammate-blockers.md)). A stream's work is teammate work at every size, one-line edits included; "the teammate can't do it right now" makes it an escalation, not lead work. Anything beyond the carve-out (more lines, multiple files, typo/cleanup passes after validation flags issues) goes through agents: even small fixes benefit from agent judgment (edge cases, conflicts, doc-specific weirdness), and agent dispatches produce auditable work products where self-edits produce only a diff. Exempt entirely: memory files (own memory namespace, not project content) and plan files (plan-mode contract), which the lead edits directly. Exploration stays inline per [no-exploration-agents](no-exploration-agents.md).
- Team-Leader Mode triggers on ANY of: the user saying "create a team" / "act as Team Leader" / "use the teams tools" / any phrasing naming the teams subsystem; OR the work itself being multi-phase implementation against an approved plan (multiple tracks, multiple sub-tasks per track, sequential or parallel dependencies, dozens-to-hundreds of files touched). The work-shape bar trips even without team phrasing from the user: standing up a team is the default for non-trivial implementation, not a special-case opt-in, and defaulting to sequential single-Agent dispatch on multi-phase plan execution is the wrong default (sequential Agent spawns are NOT team-leader behavior). Spawn teammates with `name` set so they are addressable; course corrections go via SendMessage. Once invoked, team mode persists for the conversation unless the user signals otherwise.
- Single discrete fixes (one file, one mechanical change, no plan) that exceed the lead's 1-2 line carve-out are a single Agent dispatch, and focused work gets ONE teammate: do not fan out subagents or teams for small surgical code edits or a handful of related edits in one file.
