# Team Mechanics

- 2+ parallel verification/sweep agents run as named teammates with a shared task list, never raw unnamed Agent parallelism (names, a shared task list, messaging, idle notifications, and graceful shutdowns are what the bare Agent tool lacks). Create tasks BEFORE spawning agents, each task description self-contained (the agent reads it to understand scope); agents claim tasks via TaskUpdate owner. Spawn with `run_in_background: true`; the prompt says which task to claim and to send findings back to the lead via SendMessage. Agents communicate only via SendMessage and cannot see your plain text output; their findings arrive as new conversation turns (there is no inbox to poll). Wait for all agents to report; idle notifications are normal between-turns state, not completion or failure; don't respond to them or ping until you actually need a status update. After synthesis, shut teammates down via SendMessage shutdown_request. Sizing patterns that work: ~5 verification agents (one per concern cluster), ~3 for parallel surgical edits, ~4 for path-sweeps clustered by directory group.
- TeamCreate/TeamDelete were REMOVED in Claude Code v2.1.178; the session has one implicit team (formed on first teammate spawn); `team_name` is accepted but ignored (a local hook may still require the param). Teammate display defaults to in-process (agent panel, idle rows hide after 30s); the user prefers `"teammateMode": "auto"` in settings.json for split panes. Teammates often idle after spawn waiting for a mailbox message: always SendMessage a "begin now" right after Agent-spawn, including "do not idle until pushed/done". The task list auto-offers open tasks to idle teammates ("complete all open tasks"), misrouting work across worktrees; every spawn brief must say to ignore task-list auto-offers and act only on team-lead messages. An idle ping without a report usually means still working (slow codegen), NOT stalled; do not conclude failure or spawn a duplicate early (a duplicate once double-pushed to the same branch). Session restart kills all in-process teammates silently; recovery is `git fetch`, compare origin branch heads against the last locked commits (ground truth), then check each assigned worktree's `git status` for an interrupted rebase (conflicts stay staged/frozen mid-rebase; a fresh teammate can resume it in place).
