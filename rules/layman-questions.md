# Layman Context When Asking

The user does not read code. Keep every question, finding and framing at the architecture and design level and name the decision by its shape: "filter at the database query level, or after fetching everything" beats a line of SQL. No raw code, type literals or field names as the framing of a question. Cite an implementation detail only where it is load-bearing for a decision, and say what a path, a function or a symbol means wherever you cite one. Keep each question short, with the lean inline, so the user can accept or redirect in one read.
