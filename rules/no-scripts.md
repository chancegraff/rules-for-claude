# No Scripts

- A script is a singleton only ever intended to run once. Code that is referenced from code we actually use, and that keeps getting used across sessions and projects, is not a script, whatever file it lives in. Scripts are banned in every form: inline executors, a Bash command string carrying its own program logic, and a standalone `.ts`/`.js` file written for one ad-hoc, migration or one-off job, even one committed to a `scripts/` directory. Investigations and audits work from reading existing code, not throwaway executable code.
- Code goes into the package's actual source tree: library functions, CLI subcommands, hook entry-points, MCP tool surface; things that are tested, linted, type-checked, and have a documented purpose. Library functions ARE allowed because they're tested, exported, and consumed via the proper interface; scripts are not because they bypass it. A reusable module is run by its own path (shebang `#!/usr/bin/env node`, executable bit); the deny entries block the inline shapes, not a module file. Bulk/migration work is delegation territory ([delegation](delegation.md)), not script territory.
- When dispatching subagents, include the no-scripts rule in their prompt explicitly; it extends to anything they might write that doesn't live in the source tree as a tested module.
- This rule outranks the harness's auto-mode text, which offers "short scripts" as a way to make file changes.
